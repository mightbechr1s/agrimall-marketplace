## Phase 2: Product Strategy

### Core Problem
Filipino farmers sell through middlemen who mark up prices. Buyers pay more and farmers earn less. AgriMALL connects them directly.

### Target Users
1. Farmers/Raisers: Need fair prices, direct market access, order management
2. Buyers: Want fresh produce at fair prices, direct from source
3. Admins: Platform moderation, verification, user management

### Value Proposition
"Direct from verified farms. No middlemen." - Fair prices for buyers, fair earnings for farmers.

### Key Differentiators
- Verified farmers (ID check + farm visit)
- Direct communication (no platform middleman)
- Transparent pricing (farmers set prices, capped against market average)
- Philippine-specific (peso formatting, local units, Filipino language)

## Progress Log

### 2026-11-22
- CI repaired: schema + migrations now load on MySQL 8, PHP 8.4, all migrations
  made re-runnable and TiDB-compatible (`DATABASE()` instead of a literal schema,
  no `ADD COLUMN IF NOT EXISTS`, no `USE`).
- Migration 033 (`geocode_cache`, `geocode_jobs`) applied to TiDB production.
- Mobile API hardened to match the web rules:
  - cart add/checkout now enforce buyer roles, approved/active listings,
    min/max/stock limits, self-purchase block, address and note length limits;
  - staff order list no longer silently filters to the staff member's own id;
  - farmer overview/listings accept `farmer_id` for admin/manager;
  - admin verification returns the decrypted ID number, not ciphertext;
  - listing search now keeps category/price filters and cannot throw on a
    stray placeholder.
- Accessibility: `tests/contrast_test.php` measures every text/border token pair
  in both themes; dark-mode field borders raised from 1.31:1 to 4.0:1.
- SEO: sitemap lists public pages only and matches robots.txt; robots points at
  the absolute sitemap URL.
- Android: release build no longer requests `SYSTEM_ALERT_WINDOW` and no longer
  permits cleartext traffic; release default API base is the deployed HTTPS API.

### Remaining
1. Generate a production keystore and configure release signing before Play
   distribution (current release build uses the debug key and is test-only).
2. Set `MAIL_*` (Resend) and `STORAGE_PROVIDER=cloudinary` env vars on Render.
3. Run the Android build on an emulator/device and verify the login, browse,
   cart, checkout, order and admin journeys against the live API.
4. Add Playwright end-to-end tests for the web critical journeys.
5. Evaluate analytics/error monitoring and a monetization model; neither is
   implemented.

### 2026-11-23
- Production TiDB was live but unseeded (1 admin user, 0 listings), so the public
  marketplace looked broken. `database/seed.php` now accepts `SEED_CONFIG` (point
  it at another database) and `SEED_PASSWORD` (non-local runs must not use the
  default demo password), and stores farmer ID numbers through
  `sensitive_store()` instead of plaintext. Seeded: 2 farmers, 2 buyers,
  6 active listings, 3 orders. Demo account passwords are deliberately not
  committed to the repository.
- Farmer reports page is farmer-only again (it redirected admins to the farmer
  analytics view but the nav never linked it for them).
- Windows release builds: CMake 3.22.1 ships Ninja 1.10.2, which rejects the
  React Native codegen object paths (>260 chars). The SDK copy of `ninja.exe`
  was replaced with 1.13.2 (original kept as `ninja-1.10.2.exe.bak`), and the
  CMake configure step must complete before Gradle builds. Documented here
  because it is a local machine fix, not a repo change.

### 2026-11-23 (mobile auth + mail)
- The Android app got `401 Authentication required.` on every authenticated
  request while the same token verified against the production database. The
  Apache container was not exposing the `Authorization` header to PHP. Fixed
  with the standard re-expose rewrite in `public/.htaccess` plus a header lookup
  fallback (`REDIRECT_HTTP_AUTHORIZATION`, `getallheaders()`,
  `apache_request_headers()`) in `public/api/_bootstrap.php`.
- `.env` support: `src/bootstrap.php` loads an optional gitignored `.env` before
  the config, and the local `config/config.php` mail block now reads
  `MAIL_ENABLED`, `MAIL_PROVIDER`, `MAIL_FROM` and `RESEND_API_KEY`. Real OTP
  email therefore works locally the same way it works from host env vars; a
  value already present in the real environment always wins.
